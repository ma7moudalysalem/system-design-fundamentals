# Contributing

Thank you for taking the time to help improve this book. All feedback — big or small — is genuinely appreciated.

## How to Contribute

### Report a Correction
Found a typo, a wrong number, a factual error, or a mechanism described incorrectly?

1. [Open a Correction issue](https://github.com/ma7moudalysalem/system-design-fundamentals/issues/new?assignees=ma7moudalysalem&labels=correction&template=correction.md&title=%5BCORRECTION%5D+) using the **Correction** template
2. Include the chapter name or topic
3. State what is wrong and what it should say

### Suggest an Improvement
Want a topic covered in more depth, a system added to the case studies, or a better worked example?

1. [Open a Suggestion issue](https://github.com/ma7moudalysalem/system-design-fundamentals/issues/new?assignees=ma7moudalysalem&labels=enhancement&template=suggestion.md&title=%5BSUGGESTION%5D+) using the **Suggestion** template
2. Describe what you'd like to see and why it would help readers

### Ask a Question
Something in the book is unclear?

1. [Open a Question issue](https://github.com/ma7moudalysalem/system-design-fundamentals/issues/new?assignees=ma7moudalysalem&labels=question&template=question.md&title=%5BQUESTION%5D+) using the **Question** template
2. Mention the chapter and describe what confused you

## Guidelines

- Be specific — vague reports are hard to act on
- One issue per topic — don't bundle multiple corrections into one issue
- If you're correcting a number, say where your number comes from
- Be respectful — this is a community space for learning

## What I Do With Feedback

Every issue is read. Corrections are verified and incorporated into the next revision. Suggestions are evaluated based on scope and relevance. Questions may be used to improve unclear sections of the book.
